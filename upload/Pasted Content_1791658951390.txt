## Important relationships

- A user can belong to many workspaces.
- A workspace has many members.
- A workspace has many projects.
- A project belongs to one workspace.
- A task belongs to one project and workspace.
- A task can have an assignee who must be an authorized workspace member.
- A project can have multiple members.
- Tasks can have comments, labels, dependencies, attachments, and activity events.
- A workspace has its own subscription and billing configuration.
- Notifications belong to the intended recipient and relevant workspace where appropriate.

## Database quality

- Use UUIDs or secure equivalent identifiers.
- Use foreign keys.
- Use appropriate unique constraints.
- Add indexes for common queries.
- Use createdAt and updatedAt consistently.
- Use transactions for critical operations.
- Define deletion and archival behavior explicitly.
- Prevent orphaned records.
- Avoid storing duplicate calculated values unless required for performance.
- Use Decimal or integer minor units for monetary values, not floating-point arithmetic.

Important indexes should cover commonly queried fields, including:
- workspaceId
- userId
- projectId
- assigneeId
- status
- priority
- dueDate
- createdAt
- subscription provider IDs

Ensure unique constraints are appropriate for tenant-scoped values.

For example, workspace slugs must be unique according to the chosen routing model.
